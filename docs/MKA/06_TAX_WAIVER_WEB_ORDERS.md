## هدف
پیاده‌سازی **محاسبه‌گر بخشودگی جرائم** به‌صورت صفحه/ماژول وب (نه فقط Google Sheet)، با همان منطق اسکریپت، داخل پنل یا مسیر محافظت‌شده — خروجی «پیشنهاد سیستمی برای بررسی انسان».

---

## اصول اجباری
1. نتیجه محاسبه = **پیشنهاد**؛ برچسب واضح: «نیازمند تأیید مشاور/مدیر — جایگزین رأی سازمان نیست».
2. لاگ هر محاسبه: ورودی‌ها، درصد نهایی، مبلغ، نسخه قواعد، کاربر، زمان.
3. داده پرونده در مسیر **Admin/Staff**؛ در سایت عمومی فهرست مودیان نمایش داده نشود.
4. نسخه قواعد (`WAIVER_VERSION` / circular id) در UI و لاگ ذخیره شود.
5. در ابهام یا پرونده حساس: وضعیت `HUMAN_REVIEW_REQUIRED`.
6. پایان اسپرینت: **ZIP کامل** (`mka-project-v6`) برای بارگذاری GitHub.

## دستورات اجرایی (۱۶ مورد)

| # | دستور |
|---|--------|
| 1 | مسیر `/app/staff/waiver` یا `/_authenticated/waiver` فقط برای staff (owner/manager/expert). |
| 2 | فرم مشخصات پرونده: نام مودی، شناسه، منبع مالیاتی، سال/دوره، تاریخ ابلاغ تشخیص، قطعیت، پرداخت. |
| 3 | جدول پویا جرائم: نوع، مبلغ، قابل‌بخشش بله/خیر، جمع‌ها. |
| 4 | فرم شرایط: مراحل دادرسی، کاهش≥۳۰٪، پس از ۱ ماه اجرایی، نوع پرداخت، معافیت ۸۰٪/۴۰٪ ماده ۱۹۰، واحد تولیدی، شرط افزایش ویژه. |
| 5 | دکمه «محاسبه» با پیاده‌سازی همان فرمول اسکریپت در TypeScript (تابع خالص قابل تست). |
| 6 | نمایش نتیجه: درصد پایه پس از کسر، معافیت ۱۹۰، افزایش ویژه، **درصد نهایی**، مبلغ بخشودگی، مانده، غیرقابل‌بخشش. |
| 7 | چک‌لیست مدارک (لیست اسکریپت) با وضعیت موجود/کسری. |
| 8 | ذخیره محاسبه در DB: `waiver_calculations` + JSON ورودی/خروجی + `rule_version`. |
| 9 | هشدار UI قرمز/نارنجی: «خروجی سیستمی — تأیید انسانی الزامی». |
| 10 | لینک به منبع Drive دانش و ثبت ردیف اختیاری در Registry با doc_type مرتبط بخشنامه ۲۰۰/۱۴۰۴/۵۰۴. |
| 11 | بدون نمایش این صفحه به نقش client عمومی. |
| 12 | تست واحد برای تابع محاسبه با ۲–۳ سناریوی ثابت (سال ۱۴۰۳ نقدی بدون دادرسی؛ با ۲ مرحله دادرسی؛ با ماده ۱۹۰ هشتاد درصد). |
| 13 | تنظیمات بخشنامه در ثابت/`waiver-config.ts` قابل‌ویرایش بدون soft-code پراکنده. |
| 14 | RTL کامل و اعداد فارسی در نمایش. |
| 15 | هیچ secret در کد. |
| 16 | ZIP نهایی `mka-project-v6.zip` برای مدیر. |
